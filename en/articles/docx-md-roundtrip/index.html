Round-trip editing of Word forms through Markdown

How I write formatted Word forms, such as grant application templates with fixed instruction boxes and page limits per section, in Markdown and let Claude Code apply them. This article introduces the skill I made for it, docx-md-roundtrip.

View the skill (GitHub)

The skill was written for Japanese grant forms (JSPS KAKENHI), and its instructions are in Japanese. The approach works for any form with fixed sections.

The problem

A grant form has an instruction box for each section (“describe within N pages”) and reserves pages with empty lines. If you keep editing such a docx in place, paragraph styles and the number of empty lines drift a little each time, and the damage accumulates.

The idea

Markdown is the source of truth. The filled-in docx is never edited. Every build pours the Markdown into a blank copy of the form and creates the docx from scratch, so formatting damage cannot accumulate. At the end, Word is driven through COM to add or remove empty lines until each section starts on the page the form expects. 

application/
├── template/s-13.docx   # the blank form; never edited
├── s-13.md              # source of truth; you write here
├── s-13.docx            # output; rebuilt every time
└── figure1.png          # figures to insert

Writing the Markdown

The front matter names the blank form and the start page of each section.

---
template: template/s-13.docx
output: s-13.docx
page_targets: "2=6,3=8,4=9"
line_spacing: 220
---

# section: （概要）

Body paragraphs...

# section: ５頁以内で記述すること | table

## (1) Heading

![Figure 1　Overview](figure1.png){width=450}

A # section: line is an anchor: a string copied exactly from the form that says where the content goes. With | table, the content goes right after the instruction table containing that string.

Workflow

Table 2. Tasks and scripts
TaskScript
Find the page where each section of the form startsget_baseline.ps1
Extract text from a filled-in docx (first time)docx2md.py
Rebuild the docx from Markdownmd2docx.py
Match section page boundariesfit_pages.ps1
Export to PDF to check the resulttopdf.ps1

Day to day, I edit the Markdown and say “apply s-13.md to the docx”. Claude follows the skill: it runs md2docx and fit_pages, exports a PDF, checks the page count and layout, and then reports.

Lessons from using it

Always bring Word edits back to the Markdown

The docx often gets edited directly in Word, and a rebuild would wipe those edits. The skill tells Claude to compare the docx timestamp with the last build first; if the docx is newer, it is merged into the Markdown with docx2md_sync.py before anything else.

After adjusting figures by hand, do not rebuild

A rebuild also discards figure positions and sizes set in Word. In that case patch_body.py replaces only the text paragraphs and leaves the figures alone.

When a page overflows, cut what is said twice

When fit_pages.ps1 reports OVERFLOW, the number of overflowing lines is exactly how much to cut. Cut repetition before content: an application often states the same claim three times, in the summary, the body and the methods, and that is usually enough.

Pitfalls on Japanese Windows

  • Run Python with PYTHONUTF8=1; otherwise file I/O goes through cp932 and breaks.
  • Do not redirect docx2md.py output with PowerShell’s >; it passes through the console encoding and garbles the text.
  • Word COM returns stale page numbers unless you call Repaginate().
  • Do not keep the target docx open in Word; saves will collide.

Requirements and setup

  • Windows, Microsoft Word (COM for page fitting and PDF export), Python 3 (standard library only)
  • Place the skill folder at ~/.claude/skills/docx-md-roundtrip/. Claude Code then uses it for requests such as “update the application” or “turn this docx into Markdown”.

If you have no blank form, do not use a filled-in docx as the template; the content would appear twice. Get a fresh blank form from the distributor.
