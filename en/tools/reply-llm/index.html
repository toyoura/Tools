Reply LLM

A Thunderbird add-on that drafts your reply from the compose window. It shows the model a few emails you have sent before, so the greeting, the closing and the punctuation come out close to how you write.

It calls the OpenAI or Anthropic (Claude) API with your own key. It is plain JavaScript with no build step. The user interface is in Japanese; drafts are written in the language of the email you are replying to.

Download reply-llm-0.1.0.xpi   View the source (GitHub)

Requirements

  • Thunderbird 128 or later
  • An OpenAI or Anthropic API key

Setup

  1. Download the xpi file above.
  2. In Thunderbird, open Tools → Add-ons and Themes, choose Install Add-on From File from the gear menu, and select the xpi.
  3. Open the add-on’s Options, pick the API, enter your key and save. The connection test button (接続テスト) checks that the key works.

To run it from source, use Tools → Developer Tools → Debug Add-ons → Load Temporary Add-on and select src/manifest.json. An add-on loaded this way is removed when Thunderbird restarts. src/pack.ps1 builds the xpi.

Usage

  1. Open a reply (or reply-all) window.
  2. Click the envelope button (返信の下書き) in the toolbar.
  3. Check the original email shown in the table. The add-on uses the message ID held by the reply window, so it picks the right email even when several share the subject.
  4. Choose a policy (方針) (accept, decline, propose a date, and so on) and, if needed, write the facts in the memo (メモ): candidate dates, a reason for declining, etc.
  5. Click Write draft (下書きを書く, Ctrl+Enter). You can edit the draft in place.
  6. Insert (本文に挿入) puts it above the quoted text. Inserting again replaces the previous draft.

The popup closes when you click elsewhere, but the policy, memo and draft are kept for each reply window.

How drafts are written

The prompt is in lib/prompts.js. In short:

  • The greeting, self-introduction, closing and punctuation follow your sample emails.
  • No signature and no quote: Thunderbird adds both.
  • Things only you can decide, such as whether to accept, dates or amounts, are not decided. They are left as [要確認: …] (“to confirm”).
  • No facts that are not in the original email or your memo.

You can add your own rules in Extra instructions (下書きへの追加指示) in the options, for example “end English emails with Best regards”.

What is sent to the API

The email and parts of emails you have sent are sent to the API. Emails that contain personal data of students or business partners are sent as they are. Check your organization’s rules and the provider’s data usage policy before using it.

Table 1. What one draft sends
ContentScope
The email you are replying toSender, recipients, date, subject and body (up to 12,000 characters)
Recipients of this replyTo and CC, and your own name and address
Style samplesThe three newest emails you sent to the same person in the past year, from the Sent folder. Body only, with quotes and signature removed. If you have never written to that person, emails you sent in the past two weeks are used instead
Policy and memoWhat you chose and wrote in the popup

The number of samples can be changed in the options. Set it to 0 to send none.

Files

Table 2. Files
FileContents

Trying the popup without Thunderbird

test/mock.html fakes the Thunderbird API and the LLM response and runs the real popup.js. You can check changes to the popup or the prompt without restarting Thunderbird. Figure 1 was taken from this page. It does not work over file://, so start a local server in src: 

python -m http.server 8765
# open http://localhost:8765/test/mock.html (add ?plain for a plain-text reply)
