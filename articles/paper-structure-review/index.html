学生論文の構造をレビューする

学生が書いた論文の原稿を、文面ではなく構造のレベルで赤入れするための方法です。 Claude Code のスキル paper-structure-review を使い、逆アウトラインと主張・根拠の対応表を作らせます。

スキルを見る (GitHub)

何が難しいか

学生の原稿で直すべきところは、誤字や言い回しよりも構造にあることが多いものです。章の順序、主張と根拠のずれ、議論の置き場所です。 ところが本文を頭から読みながら赤を入れると、目は文面に引っぱられます。構造の欠陥は、段落を1つずつ読んでいても見えにくいのです。

考え方

層を分ける

文面 (誤字・言い回し・LaTeX) と構造 (論理・章立て・主張の裏づけ) を混ぜて指摘すると、どちらも中途半端になります。このスキルは構造に徹します。 文面の指摘は別のファイルに任せ、重なる指摘には“[文面レビュー既出]”と付けます。

書き直しは学生にやらせる

スキルは修正の指示書までで止め、本文には手を付けません。学生はまずアウトラインの上で構成を直し、教員の確認を経てから本文を書き換えます。 構成を考える力を学生に残すための順序です。

出力

原稿と同じフォルダの memo/structure_review.md に、決まった4部構成で書き出します。

表1 structure_review.md の構成
部中身
1. 逆アウトライン各段落の主張を1文に縮めて、段落番号付きで並べる。重複・飛躍・順序の乱れ・中身のない節が浮かぶ
2. 主張と根拠の対応表論文が掲げる主張ごとに、支える実験・図表・引用の場所を対応させ、根拠不足・矛盾・過大主張を判定する
3. 構造の修正指示優先度順に S1、S2… と番号を振る。どの段落を、どこへ、なぜ動かすかを必ず書く
4. 使い方教員と学生がこの文書をどう回すか

対応表は、たとえば次のようになります (中身は架空の例です)。

表2 主張と根拠の対応表の例
#主張 (場所)根拠判定
A提案法は少ないデータでも動く (1章 ¶3)本文中になし根拠不足。データ量を変えた実験を足すか、主張を下げる
B従来法と同等以上の精度 (要旨)表3: 0.91 対 0.93過大主張。数値は従来法より低い
C計算時間を半分にした (5章)表4OK。ただし 1章の貢献リストにない

能動的に探す欠陥

学生の論文で繰り返し出てくるものを、スキルにチェックリストとして書いてあります。

  • 要旨と結論で最も強調している成果が、序論の貢献リストにない。逆に、貢献に挙げたのに実験で示していない。
  • 序論で“〜を実現する”と言いながら、本文に裏づけがない。
  • 序論の前提と、実験の結論や制限事項が食い違う。
  • 比較対象より低い数値を主語にして“同等以上”と書く。
  • 前振りだけで結論につながらない節、どの主張にも結びつかない実験。
  • 考察に置くべき新しい議論が、結論に埋もれている。
  • 手法の節と実験の節で、同じ内容を2回説明している。
  • 段落の頭が既知の情報から始まらず、前の段落とつながらない話題が急に出てくる。

運用の型

  1. 教員: S1〜Sn を承認・却下・修正する。structure_review.md に直接書き込んでよい。
  2. 学生: 承認された指示に沿って、まず逆アウトラインの上で改訂版を作り、教員の確認を得る。構成を固めてから本文を書き換える。
  3. 誤字や表現は、文面レビューのほうに従う。

2回目以降は、既存の structure_review.md を上書きせず、前回から解消したものと新しく出たものだけを更新させます。 Overleaf と git でつないでいる原稿なら、memo/structure_review.md は学生と共有し、教員の私的なメモはローカルに置いておけます。

やらせないこと

  • 本文 (.tex や .docx) を書き換えること。成果物は structure_review.md だけ。
  • 表を埋めるために、原稿にない根拠を作ること。見つからなければ“本文中になし”と書く。それ自体がいちばん大事な指摘になる。
  • 指示を“〜すること”の羅列にすること。なぜ問題かを添え、選択肢がある論点は2案で示す。

導入

SKILL.md を ~/.claude/skills/paper-structure-review/ に置きます。 原稿のフォルダで“この論文の構成を見て”“逆アウトラインを作って”と頼むと、Claude Code がこのスキルを使います。 LaTeX は \input で分かれた原稿も1ファイルの原稿も読めます。Word の原稿は、先に本文を抜き出してから読みます。
