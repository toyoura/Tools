# paper-structure-review: 論文の論理構造レビュー

学生が書いてくる論文原稿は、文面(誤字・表現・書式)よりも**論理構造**(章立ての順序・主張と根拠のずれ・議論の置き場所)に問題があることが多い。
本文を頭から読みながらでは構造の欠陥は見えにくい。そこで**構造だけを抜き出して可視化し、教員がアウトライン上で赤入れできる状態を作る**のがこのスキルの役割。

**核心の考え方: 層を分離する。** 文面レベル(誤字・言い回し・LaTeX)と構造レベル(論理・章立て・主張の裏づけ)を混ぜて指摘すると、どちらも中途半端になる。このスキルは構造レベルに徹する。文面レベルの指摘は別ファイル(例: `feedback.md`)に委ね、重複するときは「[文面レビュー既出]」と付記して棲み分ける。

**教育方針: 書き直しは学生にやらせる。** このスキルは修正指示書までで止める。本文を勝手に書き換えない。学生がアウトライン上で構成を直し、教員の確認を経てから本文に反映する、という順序を守らせることで、学生の「構成を考える力」を残す。

## ワークフロー

### 1. 原稿を全節読む

- LaTeX: メインファイル(`main.tex` など)の `\input`/`\include` をたどり、全セクションファイルを読む。単一ファイルならそれを読む。
- Word: `anthropic-skills:docx` または `docx-md-roundtrip` で本文テキストを抽出してから読む。
- 既存の文面レビュー(`feedback.md` 等)があれば読み、棲み分けのために内容を把握する。
- 図表・数値は主張-根拠の照合に必要なので、表の値・図が示す結論・引用先も拾う。

### 2. memo/structure_review.md を出力する

原稿と同じフォルダに `memo/` サブフォルダを作り(無ければ作成)、その中に `memo/structure_review.md` を出力する。構成は必ず次の4部。テンプレートは「出力フォーマット」節を厳守する。

- 既に `memo/structure_review.md` があれば上書きせず、前回レビュー以降の差分(解消済み・新規)を surgical に更新する。
- `structure_review.md` は共有物として扱う。Overleaf 連携リポジトリでは `.gitignore` を `memo/*` + `!memo/feedback.md` + `!memo/structure_review.md` とし、共有物(feedback/structure_review)はアップ、私的メモ(memo.md 等)はローカル限定にする(既存の運用があればそれに倣う)。

1. **逆アウトライン** — 各節・各段落の主張を1文に圧縮して並べる。段落番号を振る。これを見るだけで重複・飛躍・順序の乱れ・裏づけのないスタブ節が浮かぶ。
2. **主張-根拠対応表** — 論文が掲げる主張を列挙し、それを支える根拠(実験結果・図表・引用)がどこにあるかを対応させる。根拠不足・矛盾・過大主張・貢献リストとの不一致を判定する。ここがこのスキルの心臓部。
3. **構造修正指示** — 上の2つで見つけた問題を、優先度順の具体的アクション(節の移動・統合・削除・追加、貢献リストと結論の整合)にする。各指示に見出しラベル(S1, S2, ...)を振り、教員が1件ずつ承認/却下できるようにする。
4. **使い方** — 教員→学生の運用手順(下記「運用の型」)を書く。

### 3. 検出すべき構造欠陥のチェックリスト

主張-根拠表とアウトラインを作るときに、最低限これらを能動的に探す。学生論文で繰り返し出るパターン。

- **貢献と結論の不一致**: Abstract・結論が最も強調する数値/成果が、イントロの貢献リストに項目として無い。逆に、貢献に挙げたのに実験で示していない。
- **根拠のない主張**: イントロで「〜を実現する」と言うが、本文に裏づけ(実験・図表)が無い。
- **自己矛盾**: イントロの前提や主張と、実験の結論・制限事項が食い違う(例:「Xさえあれば動く」と言いつつ実験結論は「Yも必要」)。
- **過大主張**: 比較対象より劣る数値を主語にして「同等以上」と書く等、数値と主張のトーンがずれる。
- **使われない実験/宙に浮いた節**: 前振りだけで結論に接続されない節、どの主張にも紐づかない実験。
- **議論の置き場所の誤り**: 本来「考察」に置くべき新しい議論が「結論(結果再掲)」に埋もれている。初出の議論が結論に現れるのは構造として弱い。
- **重複**: 手法節の実験計画と実験節の冒頭、プロトコル説明の二重記述など、同じ内容が複数箇所にある。
- **既知→新情報の流れの断絶**(教員の文章方針に準拠): 段落頭が既知情報から始まらず、前段落と接続しない主題が唐突に現れる。
- **パイプライン/流れの分断**: 全体像の図や手法概要が特定の節に押し込まれ、後続の節が処理の流れを分断している。

## 出力フォーマット

`structure_review.md` は必ずこのテンプレートに従う(見出し・順序を固定)。

```markdown
# 構造レビュー: <論文タイトル>

**対象:** <ファイル一覧>
**作成日:** <YYYY-MM-DD>
**位置づけ:** <文面レビューとの棲み分けを1文。既存 feedback.md があればその日付と役割分担に触れる>

---

## 1. 逆アウトライン (各段落の主張を1文に圧縮)

<節ごとに、¶番号付きで各段落の主張を1文で。スタブ節・1文段落はその旨を明記>

## 2. 主張-根拠対応表

| # | 主張 (出現箇所) | 根拠 | 判定 |
|---|---|---|---|
| A | ... | ... | **根拠不足** / **矛盾** / **過大主張** / OK など + 対応方針 |

## 3. 構造修正指示 (優先度順)

### S1. <一言タイトル>【重要度ラベル】
<問題の所在(どの段落/節)→なぜ構造的に問題か→具体アクション。選択肢がある場合は案1/案2で示し推奨を明記>

### S2. ...

## 4. 使い方

<運用の型を記載>
```

判定ラベルと重要度は太字で強調し、教員が一覧で拾えるようにする。指示は「どの段落を、どこへ、なぜ」の3点を必ず含める。抽象的な「流れを改善する」ではなく、移動先・統合先・削除対象を名指しする。

## 運用の型 (structure_review.md の「使い方」に書く内容)

1. **教員**: S1〜Sn を承認/却下/修正する(structure_review.md に直接書き込んでよい)。
2. **学生**: 承認された指示に従い、まず「1. 逆アウトライン」上で移動・削除・追加を反映した**改訂版アウトライン**を作り、教員の確認を得る。ここで構成を固めてから本文を書き換える。**本文をいきなり直さない。**
3. 文面レベル(誤字・表現・LaTeX)は文面レビュー(feedback.md 等)に従う。

## やってはいけないこと

- 本文(.tex/.docx)を書き換えない。このスキルの成果物は `memo/structure_review.md` だけ。原稿の編集は教員承認後に別途行う。
- 文面レベルの校正(誤字・言い回し)に紙面を割かない。構造に徹する。既存の文面レビューと重複する構造指摘には「[文面レビュー既出]」と付記。
- 主張-根拠表を埋めるために原稿に無い根拠を創作しない。根拠が見当たらなければ「本文中に無し」と正直に書く(それ自体が最も重要な指摘になる)。
- 指示を「MUST」の羅列にしない。なぜその構造が問題かを添え、教員が判断できる材料を渡す。選択肢がある論点は二択で示す。
