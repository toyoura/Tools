様式つき Word 文書を Markdown で往復編集する

科研費の申請書のように、指示書きの枠や節ごとのページ数が決まった Word の様式を、Markdown で書いて Claude Code に反映させる方法です。 そのために作ったスキル docx-md-roundtrip を紹介します。

スキルを見る (GitHub)

何が難しいか

申請書の様式には、節ごとの“○頁以内で記述すること”という指示書きの枠があり、空行でページが確保されています。 こうした docx を直接書き換え続けると、段落の書式や空行の数が少しずつずれていき、崩れが積み重なります。

考え方

Markdown を正本にします。記入済みの docx は直さず、毎回まっさらな様式に Markdown の内容を流し込んで docx を作り直します。 作り直すので、書式の崩れが積み重なりません。ページ割りは最後に Word を COM で動かし、節ごとの開始ページが様式どおりになるよう空行を増減して合わせます。 

申請書フォルダ/
├── template/s-13.docx   # まっさらな様式。これは編集しない
├── s-13.md              # 正本。ここを書く
├── s-13.docx            # 出力。毎回作り直す
└── figure1.png          # 挿入する図

Markdown の書き方

冒頭のフロントマターに、土台にする様式と、節ごとの開始ページを書きます。

---
template: template/s-13.docx
output: s-13.docx
page_targets: "2=6,3=8,4=9"
line_spacing: 220
---

# section: （概要）

本文の段落...

# section: ５頁以内で記述すること | table

## (1) 見出し

![図1　研究の全体像](figure1.png){width=450}

# section: の行が、様式のどこに流し込むかを決めるアンカーです。様式の中の文字列をそのまま書きます。| table を付けると、その文字列を含む指示書きの表の直後に入ります。

運用して分かったこと

Word での手直しは必ず Markdown に戻す

docx を Word で直接書き直すことは普通に起きます。そのまま md2docx を走らせると、手直しが消えます。 反映の前に docx の更新時刻を前回のビルドと比べ、新しければ先に docx2md_sync.py で Markdown へ取り込むよう、スキルに書いてあります。

図を手で調整したら、作り直さない

図の位置や大きさを Word で調整したあとは、作り直すと調整が消えます。そのときは patch_body.py で本文の段落だけを差し替え、図には触れません。

ページがあふれたら、二重に言っている箇所を削る

fit_pages.ps1 が OVERFLOW を出したら、あふれた行数がそのまま削る量です。削る先は内容ではなく、同じ主張を2回書いている箇所を優先します。 申請書は、同じ主張が概要・本文・研究方法に3回出てくることが多く、たいていそこで足ります。

日本語の Windows ならではの落とし穴

  • Python は PYTHONUTF8=1 を付けて動かす。付けないと cp932 で読み書きが壊れる。
  • docx2md.py の出力を PowerShell の > でファイルに書かない。コンソールの文字コードを通って文字化けする。
  • Word COM のページ番号は、Repaginate() を呼ばないと古い値を返す。
  • 対象の docx を Word で開いたままにしない。保存が衝突する。

動く環境と導入

  • Windows、Microsoft Word (ページ合わせと PDF 化に COM を使う)、Python 3 (標準ライブラリだけで動く)
  • skill フォルダを ~/.claude/skills/docx-md-roundtrip/ として置くと、Claude Code が“申請書を更新して”“docx を Markdown にして”といった依頼でこのスキルを使います。

様式の空のファイルがないときは、記入済みの docx を template にしてはいけません。内容が二重になります。配布元から空の様式を取り直してください。
